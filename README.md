# 中文产品方案访谈

`product-solution-discovery-zh` 是一个中文 Agent Skill：通过自适应多轮提问，把模糊的数字产品、软件、AI 产品或互联网服务想法，整理成可确认、可评审的产品方案。

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

它不会一开始就套用固定问卷，也不会把用户提出的第一个功能想法直接当成正确答案。它先识别真实问题、用户、场景、目标和约束，再逐轮处理关键歧义；遇到不能同时满足的目标时，会说明冲突、给出取舍方案，并等待用户确认。

## 快速开始

安装：

```bash
npx skills add https://github.com/chen1pengvincent/product-solution-discovery-zh -g -y
```

然后在支持 Agent Skills 的 Agent 中发起请求：

```text
使用 $product-solution-discovery-zh，通过几轮中文提问帮我理清这个 AI 产品想法，并整理成可评审的产品方案。
```

也可以直接描述需求，让 Agent 根据 Skill 的描述自动匹配：

```text
我想做一个面向销售主管的 AI 周报工具，但目标用户、MVP 和数据边界还没想清楚。请先通过几轮提问帮我理清，再输出产品方案。
```

> [!NOTE]
> 不同 Agent 对 Skill 的安装目录、显式调用语法和自动发现机制可能不同。若你的 Agent 不使用 `$skill-name` 语法，请按该 Agent 的 Agent Skills 文档安装整个仓库，并用自然语言说明要调用本 Skill。

## 它解决什么问题

产品想法经常从功能出发，却缺少对真实问题、核心用户、成功标准、MVP 边界和失败条件的共同理解。直接进入 PRD 或开发，容易把未经验证的假设固化成范围和成本。

本 Skill 将访谈过程变成一个可追踪的决策流程：

- 复用用户已经给出的信息，不重复提问。
- 每轮只提出 1–3 个强关联、高信息量问题。
- 区分事实、用户决定、假设、推断和待确认事项。
- 从根因、替代方案、失败场景和最小验证路径进行对抗式审查。
- 在关键维度达到可决策状态后，先提交成文前确认稿。
- 用户确认后，才输出正式产品方案，并停止在产品层。

## 适用范围

| 适合 | 默认不覆盖或不直接执行 |
|---|---|
| 数字产品、软件、AI 产品、互联网服务 | 硬件、线下服务或需要专门监管知识的复杂产品 |
| 产品想法梳理与需求澄清 | 完整 PRD、技术架构、任务拆解或代码实现 |
| 产品发现、方案设计、功能规划 | 自动登录账户、调用付费服务或远程写入 |
| MVP 范围界定与 PRD 前置分析 | 产品方案确认后未经授权直接施工 |

硬件、线下服务或复杂监管场景仍可用于基础澄清，但 Agent 必须明确说明专业知识边界，并把无法可靠判断的内容保留为待验证事项。

## 工作方式

1. **解析已有输入**：提取目标、用户、场景、功能想法、约束、证据和偏好。
2. **建立初始理解**：简短复述当前理解，指出最可能改变方案方向的缺口。
3. **逐轮澄清**：按照影响、不确定性、不可逆性和用户负担选择下一问。
4. **必要时研究**：仅在外部事实会实质影响方案或用户明确要求时检索；无法验证时保留不确定性。
5. **对抗式审查**：检查根因、隐含假设、替代方案、MVP 完整性、失败场景及数据与运营依赖。
6. **完整性门禁**：重大阻塞项未解决时不得成文，其他未知项必须明确标为假设。
7. **成文前确认**：让用户确认问题、结果、推荐方案、MVP 边界和关键假设。
8. **输出并停止**：生成可追踪的产品方案，不自动进入实施。
9. **停止与交接**：方案交付后停止；可建议继续验证假设、扩展成 PRD 或另行制定施工计划，但必须等待新的明确授权。

## 事实与决策账本

访谈中持续区分五类信息，避免把判断包装成事实：

| 标签 | 含义 |
|---|---|
| `[事实]` | 用户明确提供或有可靠来源支持的信息 |
| `[用户决定]` | 用户已经确认的范围、优先级或取舍 |
| `[假设]` | 尚未验证、为了继续推演而暂时采用的前提 |
| `[推断]` | 基于事实得出的判断，需要说明推导依据 |
| `[待确认]` | 缺少答案且可能改变方案的重要问题 |

## 输出内容

最终方案会按实际需要裁剪，通常覆盖：

- 执行摘要、问题与机会、目标用户和核心场景；
- 目标结果、成功指标、产品定位与价值主张；
- 推荐方案、关键用户旅程和核心能力；
- MVP、明确非目标、延后范围及进入下一阶段的条件；
- 数据、运营、外部依赖、替代方案与取舍；
- 假设、风险、失败场景、验证方法和开放问题；
- 用户原始诉求到方案内容的追踪关系；
- 风险优先的后续建议，但不自动执行。

## 访谈深度

- **快速**：只解决会改变方案方向的缺口，其他未知项明确列为风险。
- **标准**：覆盖相关产品维度，完成一次方案确认和一次对抗检查；默认使用此模式。
- **深入**：增加外部证据、替代方案、边界场景和验证设计。

停止条件由信息是否足以做决策决定，而不是预设的提问轮数。

## 兼容性与验证状态

核心 `SKILL.md` 不依赖固定模型、厂商、专用提问工具、子 Agent、文件系统或联网能力；只要 Agent 能加载类似 Agent Skills 的指令并进行普通多轮对话，核心流程就具备可移植条件。

当前发布版本已经在 Codex 中完成发现与行为验证（实测日期：2026 年 8 月；具体版本未固定），包括模糊输入、信息充分输入、自相矛盾输入，以及从多轮澄清到正式成稿的完整流程。其他 LLM 或 Agent 尚未逐一实测，因此这里陈述的是设计兼容性，不是全平台运行保证。

Agent 缺少联网、文件、图表或结构化提问能力时，Skill 会退化为普通对话流程，并把无法验证的外部事实明确标记为未验证。

### 本版本的改造

主要改造包括：

- 中文化，并限定当前版本的产品范围；
- 移除固定模型、厂商和专用工具依赖；
- 加入能力自适应与无工具降级路径；
- 加入事实与决策账本、重大歧义门禁和对抗式审查；

## 贡献

欢迎提交 Issue 或 Pull Request。建议说明真实使用场景、期望行为、当前输出与期望输出的差异，以及该变化是否会扩大现有范围或引入新的外部依赖。

修改访谈流程时，请保持以下原则：不虚构事实、不重复询问已知信息、不隐藏重大取舍、不在用户确认前成文，也不在方案确认后自动施工。
